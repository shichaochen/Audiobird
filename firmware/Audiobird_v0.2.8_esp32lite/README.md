# Audiobird v0.2.8-esp32lite（LOLIN32 Lite 版型专用）

针对「MicroPython ESP32开发板 V1.0 Rev1」这类 LOLIN32 Lite 版型做的适配。
**这块板不是标准 DevKit V1**：裸 ESP32 芯片、PCB 天线、JST 电池座（板载充电）、
CH340 串口、只有一个 RST 按键、**没有 BOOT 键**、**GPIO21 没有引出**。
继承 v0.2.1 的全部修复（录音栈溢出，见 v0.2.1 说明）。

## v0.2.8 相对 v0.2.7 的改动（Captive Portal 自动弹页 + 硬件连接表）

- **连上热点自动弹出配置页**：配置模式新增 DNS 服务（所有域名解析到 192.168.4.1），
  并把手机系统的联网探测请求（iOS 的 captive.apple.com、Android 的 generate_204、
  Windows 的 msftconnecttest）一律 302 重定向到配置页 — 与酒店 WiFi 登录页同一原理。
  预期表现：iOS 连上即弹出配置窗口；Android 多数自动弹出，个别机型在通知栏给
  「登录此网络」提示、点开即配置页；少数不弹的，手动开浏览器访问 http://192.168.4.1 即可。
- 系统探测请求不再刷新「5 分钟无操作」计时，避免配置模式被探测请求无限续命。
- 本 README 新增下方**完整硬件连接表**。

## 硬件连接表（完整）

目标板：「MicroPython ESP32 开发板 V1.0 Rev1」（LOLIN32 Lite 版型）：
裸 ESP32 芯片 + PCB 天线、CH340 USB 串口、JST 锂电池座（板载充电）、
只有一个 RST 按键、**无 BOOT 键、GPIO21 未引出**。

### INMP441 数字麦克风模块（I2S）

| INMP441 引脚 | 接到 | 说明 |
|---|---|---|
| VDD | 3V3 | 供电 1.8–3.3V，只能用 3V3 |
| GND | GND | |
| SCK | **GPIO14** | I2S 位时钟 BCK |
| WS | **GPIO27** | I2S 声道选择时钟 |
| SD | **GPIO26** | I2S 数据输入 |
| L/R | **GND** | 选左声道；固件按 ONLY_LEFT 读取，接 3V3 会没数据 |

### MicroSD/TF 卡模块（SPI）

| SD 模块引脚 | 接到 | 说明 |
|---|---|---|
| VCC | 3V3 | 裸模块/带 AMS1117 稳压的模块均可 3V3 供电（个别 5V 专用模块除外） |
| GND | GND | |
| SCK | **GPIO18** | SPI 时钟 |
| MISO | **GPIO19** | |
| MOSI | **GPIO23** | |
| CS | **GPIO5** | 片选 |

卡要求：FAT32 格式化；文件名 `ABIRD_XXXX.WAV` 顺序写入根目录。

### DS3231 时钟模块（I2C，可选但强烈建议）

| DS3231 引脚 | 接到 | 说明 |
|---|---|---|
| VCC | 3V3 | |
| GND | GND | |
| SDA | **GPIO33** | 此板没有 GPIO21！ESP32 的 I2C 可映射到任意引脚 |
| SCL | **GPIO32** | 与 33 相邻，好走线 |
| SQW / 32K | 不接 | 固件不用 |

不接 DS3231 也能跑（软件时钟估算时间，误差约数分钟/天，且文件时间戳不准），
涉及录音时刻的分析（晨昏鸣叫规律）务必接上，并用配置页「对时」校准一次。

### 板载资源（已在板上，不要重复接线）

| 资源 | GPIO | 说明 |
|---|---|---|
| 蓝色 LED | GPIO22 | 低电平点亮；录音时闪烁、配置模式常亮、配置窗口期慢闪 |
| 电池电压分压 | GPIO35 | JST 电池经板载 100k/100k 分压接入，固件读数 ×2 还原 |
| 配置触发 | GPIO0（丝印「0」） | 开机后 5 秒窗口内短接到 GND ≥0.8 秒进配置模式（见下文时序警告） |

### 电源

| 方式 | 说明 |
|---|---|
| USB（CH340 口） | 供电 + 烧录 + 串口日志（115200）三合一 |
| JST 锂电池座 | 3.7V 锂电池（注意正负极方向）；插 USB 时板载自动充电 |
| 野外部署 | 电池供电即可；太阳能板等外部电源接 USB 口或 JST（经充电管理）输入 |

### 接线注意事项

- **GPIO21 此板根本没有引出，不要按 DevKit 教程接 DS3231 到 21/22。**
- GPIO6–11 是芯片内部 Flash 引脚，任何板都不可用；GPIO1/3 是串口日志，也不要占用。
- GPIO0 是启动绑带脚：**上电瞬间绝不能为低电平**（会进 ROM 下载模式 boot:0x3），
  本固件的配置触发采样放在开机数秒之后，短接线在上电后再接、触发后及时撤掉。
- 所有模块必须共地；INMP441 与 SD 模块都用 3V3，不要误接 5V。

## v0.2.7 相对 v0.2.6 的改动（位置获取改「智能粘贴」）

实测确认：手机浏览器在 http://192.168.4.1 上调用 Geolocation 会被拒
（`Origin does not have permission to use Geolocation service` — 定位 API 只允许 HTTPS 页面，
这是浏览器规则，不是设备故障）。因此位置获取改为更顺手的路径：

- 配置页「录制地点」卡新增 **粘贴坐标** 框：在高德/苹果/Google 地图长按布点位置 → 分享/复制，
  回配置页粘贴 → 自动解析出经纬度，并按来源自动选坐标系（高德/腾讯→GCJ-02、百度→BD-09、Google→WGS-84），
  核对后点「仅保存位置」即可，全程约 10 秒；
- 也支持直接粘贴 `31.284512, 121.501234` 这样的纯坐标（经纬顺序自动判断）；
- iPhone 小技巧：自带「指南针」App 底部直接显示当前经纬度（WGS-84），照着填也行；
- 原「浏览器自动定位」按钮保留为次选（个别浏览器/系统允许时会成功）。

## v0.2.6 新增：GPS 录制地点（手机定位写入）

布点时在配置网页里给设备设定录制地点，之后每条录音都知道自己录于何处：

- **配置网页新增「录制地点 (GPS)」卡片**：
  - 「📍 获取手机定位」调用手机浏览器 Geolocation（GPS 原始坐标 WGS-84，连同精度米数）；
  - **注意**：定位 API 只允许安全页面，设备热点页是 http://192.168.4.1，部分手机浏览器会拦截
    自动定位——页面会显示失败原因，并提供手动通道：在高德/苹果地图长按布点位置读出经纬度
    填入，坐标系选 GCJ-02（百度地图选 BD-09）；
  - 可填地点名（如「同济樱花林东侧」），便于后期成批分析时识别布点。
- **存储**：位置写入 SD 卡 `CONFIG.TXT`（`LAT/LON/GEO_SYS/LOC_NAME/LOC_ACC/LOC_TIME`），一次设定长期有效。
- **每条录音的索引**：录音完成后向 SD 卡根目录 `ABIRD_LOG.CSV` 追加一行：
  `unix,datetime_utc,file,lat,lon,geo_sys,loc_name,sample_rate,record_seconds,battery_mv`
  ——WAV 文件名 ↔ 录制时间 ↔ 地点一一对应，Excel/pandas 直接打开，可与 AI 识别结果按文件名合并分析。
- **坐标系纪律**：设备端只存原始坐标 + 系别、不做转换；后期分析时统一转换到同一坐标系再用
  （WGS-84 与 GCJ-02 在国内相差可达数百米，混用会毁掉空间分析）。

## 没有 BOOT 键怎么进配置模式

GPIO0 在这块板上有引出（丝印「0」）。用一根杜邦线代替按键：

1. 杜邦线一端插 GPIO0（「0」脚），另一端碰住 GND 脚不放（或先短接好）；
2. 按一下 RST 键（或重新上电）；
3. **保持短接 2 秒**（固件开机后检测 GPIO0 低电平约 0.8 秒），再松开；
4. 板载蓝 LED 常亮 = 已进配置模式，手机连热点 `AUDIOBIRD-01-XXXX`
   （密码 `audiobird`）→ v0.2.8 起会自动弹出配置页，未弹出时浏览器打开 http://192.168.4.1 。

烧录固件时同理：若 IDE 同步失败，先短接 GPIO0→GND 再点上传、
看到 Connecting 后松开（此板有 CH340 自动下载电路时通常不需要）。

- Arduino IDE 开发板选 **ESP32 Dev Module** 即可（也可选手头顺手的

## v0.2.5 更正：进配置模式的正确时序

**不要在开机前就按住 GPIO0** — GPIO0 在上电瞬间为低电平是芯片的
ROM 下载模式（串口会显示 `boot:0x3 (DOWNLOAD_BOOT) waiting for download`），
固件不会启动。v0.2.5 的正确操作：

1. 正常上电（GPIO0 不短接）；
2. 板载蓝 LED 开始**慢闪的 3 秒内**，把 GPIO0 短接到 GND **保持 1 秒以上**；
3. LED 变常亮 = 已进配置模式，松开短接线，连热点开 http://192.168.4.1 。

另一条免按键的路（v0.2.2 已烧的也适用）：把 SD 卡插电脑，在根目录
`CONFIG.TXT` 里写一行 `FORCE_CONFIG=1`，插回上电即自动进配置模式
（固件进模式后会自动把该标志清掉）。

## v0.2.5 更正：配置窗口移到 SD 扫描之后

实测发现 v0.2.3 的窗口在 SD 初始化之前：触发后要先经历一段
无灯、无串口输出的 SD 目录扫描期（坏卡时可长达约 1 分钟），看起来像没反应。
v0.2.5 改为：SD 初始化 → 读配置 → 扫描文件序号 → RTC 检测 → **才开 5 秒
配置窗口**（串口会打印 `[CFG] 5 秒窗口: ...`，蓝灯慢闪）。窗口内短接
GPIO0→GND 保持 ≥0.8 秒，触发瞬间蓝灯变常亮，随即打印
`[BOOT] ... 模式: 配置` 并开启热点。

另：扫描耗时现在会打印在「断电续写」行末尾，如明显大于几千 ms，
多半是 SD 卡文件系统被早期崩溃/断电写伤 — 备份好录音后整卡
FAT32 重新格式化即可（序号会从 0 重新开始）。

## v0.2.5：扫描可视化 + LED 开机先关

- 实测（坏卡）：文件扫描耗时 64584ms — 怀疑早期 Guru Meditation 崩溃循环
  反复断电写坏了某个 WAV 的 FAT 簇链，每次开机扫描都要顺坏链走一遍。
  **根治：整卡 FAT32 重新格式化**（卡上是没有麦克风时的静音测试文件，无内容损失）。
- 扫描改为逐文件打印 `[SD] 扫描到 文件名 (单步耗时ms)` 并翻转蓝灯，
  格式化前后一对比便知；格式化后总扫描应 <1 秒。
- 开机 pinMode 后立即关 LED，避免低电平点亮的灯在扫描期常亮误导。
